# SafeDeal Frontend

SafeDeal은 상품 사진과 인증샷 검증을 바탕으로 안전한 거래를 돕는 중고거래 서비스입니다. 이 저장소는 데스크톱 웹 기준의 React SPA입니다.

## 로컬 실행

Node.js 22.12 이상이 필요합니다. [백엔드](https://github.com/safeDeal-platform/safeDeal-Backend)의 로컬 환경을 준비하고 8080번 포트에서 실행한 다음 아래 명령을 실행합니다.

```sh
npm ci
npm run dev
```

브라우저에서 `http://localhost:3000`을 엽니다. 백엔드의 로컬 CORS 기본값과 맞춘 주소입니다. 프런트엔드 주소를 바꾸면 백엔드의 `CORS_ALLOWED_ORIGINS`에도 같은 출처를 설정합니다.

백엔드 주소를 바꾸려면 `.env.example`을 `.env.local`로 복사해 `SAFEDEAL_API_ORIGIN`을 설정합니다. 개발 서버는 같은 출처의 `/api` 요청을 백엔드로 전달합니다. 운영에서는 CloudFront가 `/api/*`를 백엔드로 전달하고, 프런트엔드 경로를 새로고침할 때 정적 배포의 `index.html`로 연결해야 합니다. API 응답에는 SPA fallback을 적용하지 않습니다.

## 연결 범위

| 화면 | 현재 백엔드와 연결된 동작 |
| --- | --- |
| 매물 탐색 | 카테고리·지역·가격 필터, 최신순 커서 목록, 매물 상세 |
| 인증 | 이메일 회원가입·로그인·로그아웃, 세션 재발급, 이메일 인증·재발송, 비밀번호 재설정 |
| 찜 | 상세에서 찜·해제, 내 찜 목록 |
| 채팅 진입 | 매물에서 채팅방 생성 |
| 시세 | 중분류·기간별 7일/30일 집계 조회와 표본 부족 안내 |
| 마이페이지 | 알림 목록·안 읽은 개수·읽음 처리, 로그인 응답에 포함된 계정 정보 |
| 매물 등록 | 브라우저에서 초안 작성과 사진 미리보기. 서버 전송·공개는 검수 계약과 함께 연결 |

API는 백엔드의 공통 응답과 오류 형식을 사용합니다. 액세스 토큰은 메모리에 두고, 세션 재발급은 서버가 설정한 HttpOnly 쿠키로 요청합니다.

### 후속 API와 화면

| 기능 | 선행 작업과 사용자 영향 |
| --- | --- |
| 사진·거래 방식·배송비·상세 장소·검수 후 공개 | 업로드, 거래 필드, 승인 상태 전이 계약이 필요합니다. 기존 등록 API는 검증 설정에 따라 즉시 게시될 수 있어 공개 버튼을 활성화하지 않습니다. 지역이나 사진을 백엔드 응답에 없는 값으로 채우지 않습니다. |
| 내 매물 수정·삭제·상태 관리 | 쓰기 API는 있지만 현재 공개 매물 응답에 소유 여부가 없고 내 매물 목록 계약도 없습니다. 판매자 본인임을 확인하는 조회 계약이 필요합니다. |
| 키워드 검색·인기 검색어·가격순·거래 방식 필터 | 서버 목록 조회와 커서 계약이 필요합니다. 현재 최신순 조회와 서버가 지원하는 필터는 그대로 이용할 수 있습니다. |
| 채팅 목록·메시지·실시간 연결·첨부·위치 공유 | 방 생성 이후 표시와 송수신 계약이 필요합니다. 실제 메시지 ID가 없는 상태에서 읽음 요청을 보내지 않습니다. |
| 장바구니·주문·안전결제·후기, OAuth, 신고·운영자 검수, AI 시세 답변 | 각 도메인 API를 연결할 때 활성화합니다. AI 답변과 기존 카테고리 집계 조회는 별도 기능입니다. |

정책·계약을 확인할 때 [노션 정책](https://app.notion.com/p/603723c0859882cb87ce81168f5e5ea7)과 [API 명세](https://app.notion.com/p/b51723c0859883d3a4c401bd06f44ce4)를 참고합니다.

## 확인

```sh
npm run build
npm test
npx playwright install chromium
npm run test:e2e
```

브라우저 테스트는 실제 React 화면을 띄우고 백엔드 응답 형식을 재현합니다. 이미 설치된 브라우저를 사용할 때는 `SAFEDEAL_BROWSER_PATH`에 실행 파일 경로를 설정할 수 있습니다.

## 협업

- 커밋 메시지는 이모지 없이 `add:`, `fix:`, `refactor:` 등의 접두어를 사용합니다.
- 작업 브랜치는 `feature/*`이며 PR의 대상은 `dev`입니다.
- PR 제목에는 `[태그]`를 붙이고 본문에는 `## 💡 개요`와 `## 🛠️ 작업 내용`을 사용합니다.
